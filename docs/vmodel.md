# Модели в мире: физика из EXODUS-OS

Раздел `/gps vmodel` переносит из панели сервера то, что раньше жило только в
`os.exodus.bridge.vmodel` (репозиторий `EXODUS-REBORN/EXODUS-OS-PERSONAL`): модель-предмет
ставится в мир и ведёт себя как настоящий блок — держит игрока, на неё можно встать, на неё
садится игрок. Исходный репозиторий при переносе не менялся, код только прочитан.

Исходники — `src/main/java/ru/hahgps/vmodel/`.

## Из чего состоит модель

| Что | Чем рисуется | Класс |
|---|---|---|
| Вид модели | `ItemDisplay` с предметом `display_item` и `custom_model_data` из пака сервера | `ModelPackets` |
| Хитбокс (луч, касание) | чистая геометрия: `parts` модели → OBB, slab-тест | `ModelBoxes`, `ModelShape` |
| Коллизия (через модель не пройти) | невидимые шалкеры на маркер-арморстендах | `ModelSolids` |
| Точки «сесть» | невидимый арморстенд-сиденье, игрок — пассажир | `ModelSeats` |
| Плейсмент и призрак | `ItemDisplay`-призрак, зелёный/красный + проверка пересечений | `ModelEditor`, `Placement` |

Поведение оригинала сохранено намеренно:

- маркер-стенды (`setMarker(true)`, `setCanTick(false)`, без гравитации, `setCollidable(false)`)
  держат шалкеров; шалкер невидимый, без AI, `setPeek(0)`, `setCollidable(true)`, шкала
  `Attribute.SCALE` 0.25…1.0 по размеру ячейки;
- шалкеры собраны в команду `hahvcol` с `COLLISION_RULE = FOR_OTHER_TEAMS`, поэтому не
  расталкивают ни друг друга, ни игроков со стороны;
- шаг сетки коллизии — 0.55 блока (`ModelSolids.STEP`), бюджет — 40 клеток на модель, при
  превышении сетка прореживается по самой «длинной» оси;
- клетка опускается так, чтобы низ шалкера лёг на поверхность: `y - scale / 2`;
- сущности модели не горят, не целятся на игроков, не ломают блоки и не выпускают пассажира:
  `EntityDamageEvent`, `EntityTargetEvent`, `EntityChangeBlockEvent`, `VehicleExitEvent`
  отменяются для всех сущностей с нашим ключом в `PersistentDataContainer`.

## Хитбокс: `parts`

Определение из панели приносит список частей; каждая — коробка в локальных координатах модели
(центр в `0,0,0`):

```
[x1, y1, z1, x2, y2, z2]                       — обычная часть
[x1, y1, z1, x2, y2, z2, ox, oy, oz, ось, °]   — часть с поворотом вокруг пивота
```

`ось`: `1` — X, `2` — Y, `3` — Z (так кодирует панель). Без `parts` хитбокс — одна коробка из
`hitbox`. На всю модель ещё действуют `hitbox_offset` (сдвиг) и `hitbox_rotate` (поворот Y/X/Z:
сначала крен, потом тангаж, потом рыскание; при переходе из мира в локаль — наоборот).

Проверки: `ModelBoxes.raycast` (луч по частям), `overlapsAabb` (модель против блока),
`overlapsModel` (модель против модели), `envelope` (габарит для быстрого отсева). Пересечения —
по теореме о разделяющей оси (15 осей, допуск `1e-4`), каждая коробка ужимается на `0.02`, чтобы
плотно стоящие модели не считались пересекающимися.

## Каталог: панель плюс локальный файл

`PanelClient` ходит в панель EXODUS(OS) тем же протоколом, что `exodus-bridge`:

```
GET  /api/minecraft/v1/vmodels/?server=<N>            — снимок: definitions + placed
GET  /api/minecraft/v1/vmodels/?key=<ключ>&server=<N> — одна модель
POST /api/minecraft/v1/vmodels/?server=<N>            — place / remove расстановки
Authorization: Bearer <токен>
```

Токен — `plugins/HahGps/models-token.txt` (env `HAHGPS_MODELS_TOKEN`, затем `HAHTOJER_MODELS_TOKEN`).
Запросы идут через `HttpURLConnection` (умеет socks-прокси, в отличие от `java.net.http.HttpClient`),
тело разбирает свой `Json` — сторонних зависимостей нет.

Локальный `plugins/HahGps/models.yml` **дополняет** панель:

```yaml
models:
  - model_key: hahgps_furniture_chair
    display_item: minecraft:oak_planks
    custom_model_data: 20001
    allowed_faces: [FLOOR, WALL]
    hitbox: [1.2, 0.9, 1.1]
    parts: [[-0.6,-0.45,-0.55,0.6,0.45,0.55]]
    sit_points: [[0, 0.35, 0]]
    collision: true
placements:
  - id: 7b6f93a0-6a7b-4f2b-9a1e-6b0d1c2f3a4b
    world: world
    x: 10.25
    y: 64.0
    z: -3.5
    yaw: 90.0
    pitch: 0.0
    model_id: hahgps_furniture_chair
```

Формат полей совпадает с ответом панели, поэтому один разбор (`ModelParse`) читает и её ответ,
и локальный файл.

## Как это работает в игре

1. Тикер (`vmodel.tick-period`, по умолчанию 10 тиков) зовёт `VirtualModelsService.tick()`: для
   каждого игрока показываются модели в радиусе (`ModelScheduler.tickPlayer` → `player.showEntity`)
   и перерисовывается призрак редактора.
2. Постановка и снятие сразу пишутся в память и в фоне уходят в панель. Если панель недоступна,
   расстановка живёт в памяти до перезапуска — локальный файл пополняется только вручную.
3. Коллизия ставится при появлении модели (`ModelSolids.ensure`) и перекладывается, если
   изменился состав клеток; лишние шалкеры снимаются.
4. Кто видит модель, решает сервер (`showEntity`/`hideEntity`), поэтому у неактивных игроков
   сущностей не копится.

## Команды и права

```
/gps vmodel status                  — модели, расстановки, клетки, состояние панели
/gps vmodel give <ник> <ключ>       — маркер модели (без ника — себе)
/gps vmodel list [фильтр]           — ключи каталога
/gps vmodel sync                    — сразу перечитать панель
/gps vmodel reload                  — перечитать config.yml и models.yml
/gps vmodel radius <4-128>          — личный радиус видимости
/gps vmodel remove                  — снять модель, на которую смотришь
```

| Право | Что даёт |
|---|---|
| `gps.models` | ставить и снимать модели |
| `gps.models.give` | выдавать маркер |
| `gps.models.admin` | синхронизация с панелью, перечитывание каталога |

Маркер в руке: ПКМ по грани ставит модель по сетке, Shift + ПКМ — свободно в точку взгляда.
ЛКМ по модели — взаимодействие или посадка, Shift + ЛКМ — снять, ЛКМ с маркером — сменить шаг
поворота (15…180°), Shift + ЛКМ с маркером — довернуть призрак.

## Ловушки переноса

- **Координаты клеток абсолютные**: `ModelSolids.layout` отдаёт мировые координаты, базу второй
  раз прибавлять нельзя.
- **Шалкер без маркера уезжает**: только пассажир маркер-стенда.
- **`setCanTick` есть не везде** — вызов обёрнут в `try/catch`.
- **Призрак без метки модели**: иначе `idOf` считает его настоящей моделью, и он попадёт под
  удары и посадку.
- **Панель вырезает `display`** из моделей, поэтому вид в руке задаёт только `parent` модели в паке.
- **Точки «сесть» в локальных координатах** и поворачиваются вместе с моделью; проверка «место
  занято» — радиус 0.4 блока.
