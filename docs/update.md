# Автообновление HahGps

Плагин сам находит и ставит новые версии из приватного репозитория
`EXODUS-REBORN/hahgps` — рестарт сервера не нужен.

## Как это работает

1. Каждые `обновление.интервал-минут` (по умолчанию 5) минут **в отдельном потоке**
   и **молча** плагин спрашивает GitHub API о релизах. В консоль попадает только
   найденная версия или ошибка, причём одна и та же ошибка повторно не пишется.
2. Тег новее установленной версии (сравнение по числовым частям, «1.0.10» новее
   «1.0.9») — плагин уведомляет группы из `обновление.группы-оповещения` (см.
   «Оповещения» ниже) и при `обновление.авто-скачивание: true` кладёт jar в
   `plugins/hahgps/update/`. Попыток скачивания три.
3. Скачанный файл проверяется **токеном сборки** (см. ниже), и при
   `обновление.горячее-обновление: true` сразу ставится и запускается на ходу.

## Оповещения об обновлении

Сообщения в чат с префиксом плагина приходят **только приоритетным**:

- **группы** из `обновление.группы-оповещения` (по умолчанию `41, 42, 103, 555` —
  технический директор, старший техник, тех-админ, программист);
- **игроки** из `обновление.игроки-оповещения` (по умолчанию `haker_one`) —
  получают оповещения независимо от группы.

Оба списка меняются в `config.yml` и перечитываются через `/gps update reload`,
текущее содержимое видно в `/gps update status`.

Проверка групп идёт по **LuckPerms**: основная группа и унаследованные, без
учёта прав и статуса оператора. Если LuckPerms не установлен, берётся только
**явно выданное** право `group.<имя>` из `getEffectivePermissions()`, поэтому
«звёздочка» оператора и право `gps.admin` **не считаются** — обычный OP
оповещения об обновлении не получает. Игрок из списка имён получает их в любом
случае (регистр не важен).

Порядок сообщений при нахождении новой версии:

1. «Доступно новое обновление: {версия} · вышло: {дата}» — дата релиза из
   GitHub (`published_at`), формат `dd.MM.yyyy`.
2. «Что нового: {заметки}» — текст релиза из GitHub (`body`); слишком длинные
   обрезаются, пустые пропускаются.
3. «Скачиваю обновление…» — перед скачиванием.
4. Результат: «Обновление {версия} успешно установлено — сервер не
   перезапускался» (горячая подмена), «Обновление {версия} скачано и проверено —
   готово к установке» (без горячей подмены) либо «Обновление не удалось:
   {ошибка}».

Каждое оповещение дублируется в лог сервера. Оповещение о новой версии и списке
«что нового» приходит один раз на версию; «скачиваю» и результат — на каждую
попытку.

## Горячая подмена

Всё выполняется в главном потоке, доли секунды, игроки остаются онлайн:

1. новый jar копируется в `plugins/hahgps-<версия>.jar` (до этого шага ничего не
   тронуто — ошибка копирования безопасна);
2. у старого экземпляра закрываются открытые меню игроков и снимаются его команды
   с командной карты (иначе `/gps` остался бы за выгруженным плагином и отвечал
   «plugin is disabled», а из «мёртвого» меню можно было бы забрать предметы);
3. `disablePlugin` сохраняет данные и закрывает classloader старого плагина
   (заодно отпускается блокировка jar-файла — важно для Windows);
4. старый экземпляр снимается с реестров менеджера плагинов (иначе Paper отвечает
   `attempted to add duplicate plugin identifier`);
5. `loadPlugin` + `enablePlugin` поднимают новую версию, старый jar удаляется,
   дерево команд Brigadier пересобирается.

**Сбой после выгрузки — откат**: прежний jar грузится обратно, версия помечается в
`update/hot-failed.txt` (автоматический повтор запрещён), причина идёт в лог и
группам оповещения. Обновление встанет при следующем рестарте; вручную — `/gps update apply`.

**Если загрузчик уже закрыт, подмена не начинается.** Paper закрывает classloader
плагина в `disablePlugin`, а если сервер потом поднял тот же экземпляр обратно
(перезагрузка, плагин-менеджер, неудачная подмена), уже загруженные классы
работают, а любой новый падает с `zip file closed`. `update/LoaderState` проверяет
загрузчик по ресурсам своего jar (`plugin.yml`, `hahtojer.token`) до копирования
файла: при закрытом загрузчике плагин один раз пишет в лог и группам «нужен
перезапуск», помечает версию в `hot-failed.txt` и больше не повторяет попытки.
Всё, что нужно подмене после выгрузки (`HotSwap.Result`, `LoaderState`), прогревается
при включении плагина (`HotSwap.prime`), чтобы сообщение об ошибке не превращалось
в стектрейс. Тот же случай ловится и после `enablePlugin`: если сервер вернул
прежний экземпляр или его закрытый загрузчик, подмена не объявляется успешной —
новый jar убирается, версия применится при рестарте.

Если на Windows старый файл удалить не дало, плагин переименует его в
`hahgps-<версия>.jar.old` (Paper грузит только `*.jar`) и напишет
`update/apply-update.cmd` для остановленного сервера. При
`обновление.горячее-обновление: false` плагин только скачивает jar и подменяет
файл **при выключении** сервера.

## Токен сборки (`hahtojer.token`)

`src/main/resources/hahtojer.token` — 64 hex-символа, **один и тот же во всех
версиях** (и совпадает с токеном основного плагина hahtojer). Файл лежит внутри
каждого jar из репозитория.

| Правило | Как сделано |
|---|---|
| Назначение | не защита от подмены, а отлов обрезанной закачки, страницы ошибки прокси и чужого jar |
| Сравнение | плагин берёт токен из classpath, у скачанного jar читает тот же файл и сверяет (`update/BuildToken`) |
| Когда | **до** переноса файла на диск; файл из `update/`, найденный при старте, проверяется так же |
| Размер файла | **не проверяется**: у плагина нет постоянного веса, порог лишь мешал бы обновлению |
| Состояние | видно в `/gps update status` |

Токен задавать и менять при выпуске не нужно — он уже в репозитории.

## Токен доступа к GitHub

Без токена приватный репозиторий отвечает `404`. Нужен fine-grained токен с правом
**Contents → Read-only** на `EXODUS-REBORN/hahgps`.

| Порядок | Источник | Когда удобно |
|---|---|---|
| 1 | `HAHTOJER_GITHUB_TOKEN` (переменная окружения) | systemd, Docker-секреты |
| 2 | `plugins/hahgps/github-token.txt` | основной способ |
| 3 | `plugins/hahtojer/github-token.txt` | **если основной плагин hahtojer уже настроен — отдельный токен для hahgps не нужен, он берётся оттуда** |
| 4 | `обновление.ключ` в `config.yml` | запасной вариант |

Файл `plugins/hahgps/github-token.txt` плагин **создаёт сам** при первом запуске:
копирует из jar шаблон с инструкцией и строкой-заглушкой `ВСТАВЬ_ТОКЕН_СЮДА`. Пока
заглушка на месте, своего токена у плагина нет — и он идёт смотреть в папку
`plugins/hahtojer/`. Строки с `#` игнорируются, BOM, кавычки и префиксы `token=` и
`Bearer` снимаются. Токен в лог не пишется и в git не попадает.

## Настройки (`config.yml` → секция `обновление`)

| Ключ | По умолчанию | Значение |
|---|---|---|
| `включено` | `true` | автопроверка релизов |
| `репозиторий` | `EXODUS-REBORN/hahgps` | откуда брать релизы |
| `предрелизы` | `false` | ставить ли предрелизы |
| `интервал-минут` | `5` | период проверки (0 — выключить периодичность) |
| `файл-ключа` | `github-token.txt` | имя файла с токеном доступа |
| `авто-скачивание` | `true` | скачивать найденную версию |
| `горячее-обновление` | `true` | ставить на ходу, без рестарта |
| `группы-оповещения` | `41, 42, 103, 555` | группы LuckPerms, которым приходят оповещения об обновлении (не OP и не `gps.admin`) |
| `игроки-оповещения` | `haker_one` | ники, которым оповещения приходят независимо от группы |
| `адрес-api` | `https://api.github.com` | для GitHub Enterprise |
| `ключ` | пусто | запасной токен доступа в самом конфиге |

## Пререлизы (свой сервер, без GitHub)

Второй, независимый канал: тестовая сборка лежит на `https://pre.hakerone.ru` и ставится сама,
релиз в GitHub для этого не нужен. Включается сам, когда в `plugins/HahGps/keyydev.txt` появляется
ключ (файл плагин создаёт при первом запуске с заглушкой; если своего ключа нет — берётся
`plugins/hahtojer/keyydev.txt`).

| Ключ (`config.yml` → `пререлизы`) | По умолчанию | Значение |
|---|---|---|
| `включено` | `true` | выключает канал целиком, даже если ключ на месте |
| `адрес` | `https://pre.hakerone.ru` | сервер пререлизов |
| `проект` | `hahgps` | имя проекта в хранилище |
| `файл-ключа` | `keyydev.txt` | файл с ключом в папке плагина |
| `прокси` | пусто | прокси для канала, если сервер не достаёт Cloudflare напрямую: `socks5h://127.0.0.1:2080` (ставит `socksProxyHost`/`socksProxyPort` на JVM) или `http://host:port`; env `HAHTOJER_DEV_PROXY` |
| `интервал-минут` | `2` | период проверки (минимум 1) |
| `авто-скачивание` | `true` | скачивать новую сборку сразу |
| `горячее-обновление` | `true` | ставить на ходу через `HotSwap` |

Версии пререлизов — своя последовательность `1.0.0 … 1.0.9 → 1.1.0` (разряды 0–9, на девятке
перенос), номер присваивает сервер при публикации. В jar правится `plugin.yml` на
`<база>+dev<номер>` (например `1.6.8+dev1.0.2`) и добавляется `devbuild.txt`, поэтому релиз `1.6.8`
тестовую сборку не перезапишет, а `1.6.9` — заменит. Сборка ставится, только если её база не старше
установленной версии: канал не может откатить сервер назад.

Публикация и инфраструктура — в `AGENTS.md`, раздел «Пререлизы»; сам инструмент —
`python3 docs/devrelease/publish.py --project hahgps --jar target/hahgps-<версия>.jar`.

## Команды

| Команда | Что делает |
|---|---|
| `/gps update status` | версия, репозиторий, автопроверка, горячая подмена, токен, что готово |
| `/gps update check` | проверить GitHub прямо сейчас |
| `/gps update install` | проверить, скачать и поставить на ходу |
| `/gps update apply` | поставить подготовленный jar без рестарта |
| `/gps update dev` | проверить и поставить пререлиз с `pre.hakerone.ru` |
| `/gps update devcheck` | только проверить канал пререлизов |
| `/gps update reload` | перечитать настройки секций `обновление` и `пререлизы` |

Право — `gps.admin`.

## Проверка релиза вручную

Скачать вложение `hahgps-X.Y.Z.jar` из релиза и распаковать его как zip: внутри
обязан лежать `hahtojer.token` с тем же значением, что
`src/main/resources/hahtojer.token` в репозитории. Нет токена или значение другое —
плагин файл не поставит.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `GitHub ответил 404` | нет токена или доступа к репозиторию | вписать токен в `plugins/hahgps/github-token.txt` (или настроить hahtojer) |
| `GitHub ответил 401/403` | токен истёк или без нужного права | перевыпустить fine-grained с Contents: Read-only |
| `Подходящих релизов с jar-файлом не найдено` | релиз с вложением не создан | проверить, что тег `vX.Y.Z` запушен и Actions отработал |
| `в скачанном файле нет hahtojer.token` | вместо jar пришёл ответ прокси или чужой jar | плагин пробует 3 раза, дальше проверить сеть/VPN/антивирус |
| `токен сборки в скачанном файле не совпадает` | файл не наш | проверить токен в релизе и перевыпустить версию |
| `Горячая подмена до X не удалась` | новая версия не загрузилась, вернули прежнюю | причина в логе; `/gps update apply`, иначе встанет при рестарте |
