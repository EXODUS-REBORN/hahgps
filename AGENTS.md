# HahGps — правила для агентов

## Коммиты и релизы

- Один релиз — **один коммит**. Не дробить на атомарные коммиты: весь релиз
  (код, тексты, `release-notes.txt`, версия в `pom.xml`, история в `README.md`) —
  одним коммитом `vX.Y.Z: …`, затем пуш и тег `vX.Y.Z`.
- Коммитить **только** при выпуске релиза. Без релиза — не коммитить.
- Пуш — **в оба remote**: `git push origin main --follow-tags` (GitHub, от него
  работают CI и релизы) и `git push forge main --tags` (локальный Forgejo).
  После зелёного GitHub-релиза зеркалировать его на форж:
  `~/.local/bin/forgejo-release-sync.py EXODUS-REBORN/hahgps` (идемпотентно).

## Релизные заметки (обязательно каждый релиз)

- Краткое описание изменений релиза живёт в `src/main/resources/release-notes.txt`.
- Формат: **1–2 предложения, до ~200 символов**, plain text без MiniMessage-тегов.
  Должно понятно описывать, что добавилось/изменилось в этом релизе.
- Тот же текст идёт в GitHub Release notes и в строку «История версий» в `README.md`.
- При каждом релизе (смена `<version>` в `pom.xml`) обновить все три места:
  `release-notes.txt`, GitHub Release, `README.md`.
- Стартовый баннер (`ConsoleBanner`) печатает этот текст одной строкой
  `└ Что нового: …` — баннер всегда короткий, консоль не засираем.

## Консольный баннер

- После логотипа максимум 3 строки: статус+версия, команды, «Что нового».
- Никаких палитр, списков цветов и простыней в консоль.

## Ресурспак (обязательно при правках предметов)

- Любое изменение моделей, текстур, `CustomModelData` или блоков-предметов
  (трекеры, локаторы, стрелки и т.п.) — это изменение **ресурспака**.
  Без него игрок видит ванильный предмет, даже если код обновлён.
- После правок: `python3 respack/build.py` (собирает `dist/hahgps.zip`, кладёт
  копию в `src/main/resources/hahgps.zip` и рендерит превью), затем собрать jar.
- Публичный пак для `/gps pack` живёт отдельно: обновить
  `EXODUS-REBORN/hahgps-pack` (`hahgps.zip` + скриншоты) и запушить, иначе
  игроки продолжат качать старую версию по старому URL.
- Предметы, которые ставятся блоком, требуют `blockstate`; одного item-диска
  недостаточно.
- В релиз прикладывать **реальные скриншоты** из `respack/preview/` (и копии в
  `docs/screenshots/`), а не голые ссылки. В чат обновления картинки не
  отправлять: `UpdaterService.shortNotes` вырезает markdown-скриншоты.
