# HahGPS — Архитектура плагина

## Обзор

HahGPS — плагин навигации для Minecraft сервера (Paper/Spigot API). Позволяет игрокам создавать точки интереса (POI), строить маршруты между ними, визуализировать дорожную сеть и получать навигационные подсказки в реальном времени через BossBar, ActionBar и частицы.

## Технологический стек

- **Язык:** Java 17+
- **Платформа:** Paper API (совместим с Spigot)
- **Сборка:** Maven
- **Хранение данных:** SQLite (по умолчанию) или MySQL
- **Визуализация:** Adventure API (MiniMessage), BossBar, ActionBar, частицы
- **Обновления:** GitHub Releases API с горячей подменой jar

## Ключевые компоненты

### 1. HahGpsPlugin (главный класс)

Точка входа плагина. Управляет жизненным циклом:
- `onEnable()` — инициализация конфигурации, запуск хранилища в асинхронном потоке
- `onDisable()` — остановка сервисов, закрытие соединений
- Хранит ссылки на все сервисы (синглтон через `getInstance()`)

### 2. Система команд

Иерархическая структура команд через интерфейс `SubCommand`:
- **MenuCommand** — главное меню
- **PointCommand** — управление точками (create, delete, info, rate, list)
- **CategoryCommand** — управление категориями (create, delete, list)
- **GotoCommand** — навигация к точке
- **SearchCommand** — поиск точек
- **RouteCommand** — управление маршрутом (start, stop)
- **LogCommand** — переключение подсказок
- **ReloadCommand** — перезагрузка конфигурации
- **UpdateCommand** — управление обновлениями
- **HelpCommand** — справка
- **EdgeCommand** — управление рёбрами графа
- **VisualCommand** — визуализация дорожной сети
- **ItrakCommand** — трекеры iTrak: give, give-locator (радиус/long),
  give-terminal, scan, find (свои трекеры + карта), list, info, route, name
  (переименование), open (карточка), take, remove, watch

### 3. Слой данных (Storage)

**StorageProvider** — интерфейс для работы с БД:
- `SqliteStorageProvider` — файловая БД (по умолчанию)
- `MysqlStorageProvider` — серверная БД

Схема БД — **v5**: к таблицам точек, категорий, оценок, маршрутов и рёбер
добавлены `trackers` (уникальный код, цвет, водозащита, координаты, привязка к
сущности, опорный блок, время последнего движения) и `itrak_terminals` (блоки-
терминалы по координатам). В `meta` лежит порядковый счётчик кодов трекеров и
версия схемы. Старые базы мигрируют при открытии, недостающие колонки
дозаполняются, дубли кодов трекеров вычищаются перед созданием уникального
индекса.

**DataService** — асинхронный слой с кэшированием:
- Кэширует категории и точки в памяти
- Выполняет все операции с БД в фоновом пуле потоков
- Предоставляет `runSync()` для возврата на главный поток

### 4. Дорожный граф и навигация

**RoadGraph** — неориентированный граф:
- Узлы (`GraphNode`) — точки мира
- Рёбра (`GraphEdge`) — связи с весом и допустимыми типами транспорта

**Pathfinder** — алгоритм A*:
- Поиск кратчайшего пути с учётом скорости транспорта
- Ограничение на количество расширений (100 000)
- Поддержка мультимодальных маршрутов

**WalkGrid / WalkPathService** — пеший путь по блокам, когда граф дорог не даёт
маршрут: A* по клеткам (шаг, прыжок на блок вверх, падение до трёх блоков вниз),
стены, лава и огонь обходятся. Сам алгоритм не зависит от Bukkit и покрыт
тестами, доступ к блокам — через прослойку, расчёт идёт в главном потоке
порциями по 1200 клеток за тик.

**NavigationService** — управление навигацией:
- Создаёт сессии навигации для игроков
- Обновляет BossBar (Adventure API) с нарисованной стрелкой и расстоянием
- Отправляет подсказки в чат: префикс, тот же глиф стрелки, локальный текст
- По смене направления не спамит: ключ последней строки/подсказки хранится в сессии

**ResourcePackService** — раздача пака стрелок:
- Читает встроенный `hahgps.zip` из jar (или берёт `resource-pack.url`)
- Поднимает HTTP-сервер на `resource-pack.port` и отдаёт только этот файл
- `resource-pack.host` или адрес интерфейса default-маршрута попадает в URL
- Пак отправляет только команда `/gps pack`; при входе — никогда

### 5. Визуализация

**VisualizationService** — отрисовка дорожной сети:
- Частицы вдоль рёбер графа в радиусе 64 блоков
- Цвет частиц зависит от типа транспорта
- Пространственная сетка рёбер (ячейка 64 блока, строится на ревизию графа):
  на кадр берутся только окрестные рёбра, а не весь граф с сортировкой
- Бюджет 160 частиц на игрока за кадр, шаг точек 4 блока: каждый вызов
  `spawnParticle` — отдельный пакет, и раньше пять включённых типов давали
  до 3000 пакетов в секунду на зрителя

**MapService** — карты Minecraft:
- Рендеринг ландшафта в `BufferedImage` (картинка живёт по номеру `MapView`, а
  рендерер ставится на вид ровно один раз — раньше копился на каждое открытие)
- Отображение POI, маршрута, игроков и своих трекеров
- Следование за игроком (`map.follow-player`) и ручная панорама Shift+мышью
- Выдача предмета-карты и перекладывание её в главную руку (иначе клиент её не рисует)
- Чужие ванильные карты не трогает: карта опознаётся по PDC-метке и модели

**TerrainRenderer** — порционный рендеринг:
- Выборка блоков на главном потоке (квота 1024 за тик, полотно — 16 тиков)
- Отрисовка в фоновом потоке, одна пачка `setRGB` вместо 16 384 вызовов
- Кэш снятой поверхности по «мир + центр + масштаб» (TTL 20 с): маркеры
  рисуются поверх, а ландшафт не пересчитывается на каждый кадр
- Догрузка ближайших чанков строго в пределах бюджета (16–32 за рендер,
  только незагруженных); остальное берётся из кэша мира
- Задача сэмплирования хранится и отменяется при выключении; её падение
  не оставляет future незавершённым
- Поддержка масштабов карты (CLOSEST — FARTHEST)

### 6. GUI-система

**GuiScreen** — базовый класс экрана:
- Управление инвентарём
- Обработка кликов
- Навигация между экранами

**GuiTheme** — стилизация:
- RGB-палитра из 28 цветов: базовая синяя линейка (`TONES`) + акценты (`ACCENTS`)
- Градиенты, декорации `<bold>`/`<italic>`, мини-шрифт `uniform` — только время и версии
- Обрезка текста под границы окна (28), имени (30) и подсказки (40)
- Кнопки навигации (назад, вперёд, закрыть)

**InputManager** — ввод через чат:
- Запрос текста у игрока
- Таймаут 60 секунд
- Перехват сообщений через `AsyncChatEvent`

### 7. Система обновлений

**UpdaterService** — проверка обновлений:
- Опрос GitHub Releases API
- Скачивание jar с проверкой токена сборки
- Горячая подмена без рестарта сервера

**HotSwap** — горячая подмена:
- Копирование нового jar в plugins/
- Выгрузка старой версии через PluginManager
- Загрузка и включение новой версии
- Откат при ошибке

**BuildToken** — проверка подлинности:
- Сравнение токена в jar с эталоном
- Защита от подмены файла обновления

### 8. Поиск

**SearchService** — нечёткий поиск:
- Алгоритм Левенштейна для сравнения строк
- Быстрый отсев по разнице длин
- Настраиваемый порог похожести

**FuzzyMatcher** — утилиты сравнения:
- Расстояние Левенштейна
- Верхняя оценка похожести
- Нормализация регистра

## Потоки и синхронизация

Плагин использует многопоточную модель:

- **Главный поток (Bukkit)** — все операции с миром, инвентарями, событиями
- **Пул БД (2 потока планирования, 1 соединение)** — все запросы к хранилищу
- **Пул рендера (1 поток)** — отрисовка карт

Синхронизация:
- `DataService.runSync()` — переход на главный поток
- `SubCommand.runSync()` — безопасный переход с проверкой состояния плагина
- `ConcurrentHashMap` — для кэшей, читаемых из разных потоков
- `synchronized` — для операций с графом и хранилищем

## Конфигурация

**config.yml**:
- `language` — язык сообщений (ru/en)
- `storage.type` — тип хранилища (sqlite/mysql)
- `storage.sqlite.file` — файл БД SQLite
- `storage.mysql.*` — параметры подключения MySQL
- `navigation.*` — настройки навигации (интервал, радиус прибытия, цвета BossBar)
- `map.*` — настройки карты (масштаб, отображение POI/маршрута)
- `search.*` — настройки поиска (макс. результатов, порог похожести)
- `transport.*` — доступные типы транспорта
- `default-categories` — стандартные категории
- `обновление.*` — настройки системы обновлений

## Модель данных

### Таблицы БД

**categories**:
- `id` — первичный ключ
- `name` — уникальное имя
- `is_default` — признак стандартной категории

**pois**:
- `id` — первичный ключ
- `name` — уникальное имя
- `category_id` — ссылка на категорию
- `world`, `x`, `y`, `z` — координаты
- `description` — описание
- `author` — создатель
- `created_at` — метка времени

**ratings**:
- `poi_id` + `player_uuid` — составной ключ
- `rating` — оценка 1-10

**routes**:
- `id` — первичный ключ
- `name` — уникальное имя
- `world`, `transport`, `created_by`, `created_at`

**route_nodes**:
- `id` — первичный ключ
- `route_id` — ссылка на маршрут
- `seq` — порядковый номер
- `world`, `x`, `y`, `z` — координаты узла

## Безопасность

- Все пользовательские данные экранируются перед выводом в MiniMessage
- Проверка прав доступа для каждой команды
- Защита стандартных категорий от удаления
- Проверка подлинности jar при обновлении
- Таймауты на все сетевые запросы
- Обработка исключений на всех границах потоков
